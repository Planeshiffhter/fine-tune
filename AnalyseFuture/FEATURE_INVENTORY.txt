F01: Prompt validation and safe rendering
-----------------------------------------
Purpose: Reject unsupported prompt input and escape text inserted into static HTML.
Current implementation/status: Implemented offline; exercised by existing unit/API tests. No formal proof of all browser behavior.
Owned files/services:
  - packages/core/src/index.mjs
  - packages/core/test/core.test.mjs
Dependencies:
  - JavaScript Unicode strings and RegExp; no external packages
Existing verification:
  - core tests: reject missing/short/long/control-character prompts; preserve trimmed Unicode/newlines; escape hostile HTML; reject generated script/network assets
Missing or unverified functionality:
  - No content policy or arbitrary generated-code security boundary; rendering only escapes template substitutions.
Recommended active location: packages/core
Consolidation decision: Keep validatePrompt, escapeHtml and InputError together with deterministic rendering; API reuses InputError instead of duplicating validation.

PUBLIC EXPORTS AND COMPATIBILITY
================================
packages/core exports InputError, validatePrompt, escapeHtml, selectTemplate and
generateMockProject. The API imports generateMockProject and InputError from the
@fine-tune/core workspace export. Its response shape includes status, provider,
category, title, plan, verification and files. Preserve mock-only/unrun labels.

apps/api exports createHandler for tests; server.mjs remains the process entrypoint.
HTTP surface: GET /api/health; POST /api/generate; GET /, /app.js and /styles.css.
Unknown endpoints return 404; known routes reject unsupported methods with 405.
No command execution endpoint, customer database, auth or deployment API exists.

model-gateway exports ModelGatewayError, MockModelProvider, OllamaModelProvider,
ModelGateway, createModelGateway and createModelGatewayFromEnv. Its provider
interface is name + generate() + stream(); custom provider replacement is tested.

agent exports AgentAdapterError, OpenHandsAgentServerAdapter and
createOpenHandsAgentAdapterFromEnv. Adapter lifecycle operations retain existing
argument/result contracts. Changes to network redirect policy must be documented
as safety behavior, not represented as a new coding-agent implementation.

Cross-service integration is not a relocation: the browser/API calls the core
mock directly. It does not call the gateway or agent. Those adapters do not call
each other. Future orchestration needs an explicit, bounded contract and a real
vertical-slice test; a folder merge cannot supply that behavior.

FRAMEWORK AND LANGUAGE BOUNDARIES
================================
The active product is Node.js ESM JavaScript with native HTTP/fetch and a static
HTML/CSS/DOM frontend. There is no active React/Next.js build or TypeScript
compiler. The five private npm workspaces require Node >=22 and contain no
external npm runtime/development dependencies. API depends only on internal core.

OpenHands upstream is primarily Python behind an optional REST server. OpenSandbox
contains Python/Go infrastructure plus language SDKs. Their preserved archives
are references, not active product packages. A single product can retain these
language boundaries through reviewed SDK/API contracts without rewriting them.

ARCHIVE/TEST EXECUTION BOUNDARY
==============================
At baseline, npm test used bare node --test with no explicit AnalyseFuture
exclusion. Compressed ZIPs and Markdown snapshots were not runnable tests, but
future unpacked .test.mjs/.js files there could be discovered. Recovery scopes
test discovery to trusted active test files; retain archives compressed and keep
future extraction outside checkout. Excluding AnalyseFuture from package
workspaces alone does not constrain Node test discovery.
Use the final explicit test-file configuration and keep archives compressed.
The application server serves an asset allowlist and does not expose AnalyseFuture.
These controls reduce accidental execution/disclosure; they do not make archived
code trusted or provide a general malicious-code sandbox.
